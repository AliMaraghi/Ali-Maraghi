# APEX v4.4 — Adversarial Self-Audit, Root Causes, and Repair Ledger

## Verdict before praise

The previous development approach over-promised. It frequently confused a running `healthz`, passing synthetic unit tests, many source files, or large token usage with measurable system capability. A local prototype with dozens of passing tests can be valuable engineering evidence but is not an autonomous, global, continuously learning agent, a financially productive company, a finished film studio, or a production-grade private iPhone control centre.

## Case against my own solution

**A. 'Four layers' can be a decorative diagram.** A four-box architecture without enforcement gives no security or correctness benefit. Repaired with explicit module boundaries, fail-closed contracts and cross-layer negative tests. Still needs actual network/runtime boundaries in a staged deployment.

**B. 'Open world' can conceal a bounded, generic opportunity list.** Giving six example source families is insufficient to claim open-world search. Repaired by accepting arbitrary lawful geography, sector, mechanism and customer-problem axes with bounded generation and typed evidence. Actual global coverage and source-lane discovery still require connectors, coverage measurement and real-world verification.

**C. 'Independent critic' can agree with the generator.** Three generated objections may be the same bias repeated. Repaired by distinguishing critic *test plans* from proof, and requiring independently graded, real holdouts before even owner review. Yet truly independent evidence gathering and evaluator staffing remain unsolved.

**D. 'Evolutionary' can be stochastic prompt churn.** Candidate score gains on 12 synthetic cases tell us only the scoring pipeline works. Repaired by pairing cases exactly, disallowing training splits, requiring case hashes, rejecting severe regressions and gating human review. Statistical calibration, drift and real longitudinal testing remain unmet.

**E. All 18 'agents' can be labels.** Repaired by a 18-slot registry with `NOT_IMPLEMENTED` default; a slot becomes `TESTED` only with runnable invocation, negative tests and evidence. This still does NOT deliver 18 agents, nor should we claim otherwise.

**F. 24/7 operation can be a monitoring illusion.** Container `Started` or database connected says nothing about all workflows, retries, lock contention, disk, external APIs or backup restore. Repaired with an explicit SLO target and reliability gates; actual constant operation requires on-server workers, health probes, monitoring and recovery drills.

**G. iPhone PWA can be vaporware.** A local or loopback endpoint cannot be reached securely from the iPhone by itself. Repaired as a separate gated production deliverable with owner authentication, protected domain routing, safe storage and approval UI. Not delivered in this ZIP.

**H. Corporate/private data leakage risks rise with broad 'life integration'.** A single all-knowing dossier violates minimisation. Repaired by isolated domain rules and default rejection of all sensitive/professional data in this offline demo. Real encryption, KMS, lawful source consent and deletion rights remain absent.

**I. A 'huge' code base can have more defects.** Our first offline run found a URL parser flaw that allowed private IPv4 literals: an exception handler inadvertently swallowed `ApexError` because it subclasses `ValueError`. Fixed the root cause (separate parsing from policy rejection) and added regression tests. Earlier tests also had a wrong dataclass call and were repaired. This is a concrete self-repair, not evidence of general self-improvement.

**J. An exact textual recovery claim can be false.** The available master source explicitly says older source passages are lost; it proposes 8-1..14 role completions and contains six §5 operational layers. The four high-level macroplanes in this package are therefore a **new reconstruction**, not verified verbatim historical copy. The exact abbreviation OWP does not appear as such; its named concepts do. Preserve that uncertainty.

**K. Money and time limits do not disappear by using free plans.** A model token quota is not an API budget, and £20 of prospective budget is not authorisation. This package makes no billed calls, and a production gateway must reserve actual money across currencies and model changes.

**L. More specialists need not make Apex 'beyond humans'.** Uncontrolled subagents repeat errors, consume time and introduce failure surfaces. Adopt specialists only where independent held-out evaluation proves incremental utility against simpler off-the-shelf alternatives.

## Mandatory residual weaknesses / engineering debt

1. SQLite hash-linked log is not genuinely append-only against a privileged writer; production needs separate immutable audit sink and independently protected signing keys.
2. URL parser is **not** an HTTP fetcher and does not enforce network/DNS/redirect destination; production requires vetted egress enforcement and real tests.
3. Declared publisher identity and independence are self-reported; trusted evidence fetching, signatures/metadata and human/independent study remain required.
4. No source connectors, no data ingestion daemon, no LLM adapter, no verified demand, no purchases or calls, no network.
5. No SQL migrations to production PostgreSQL, no streaming monitors, no real n8n orchestration.
6. No actual iPhone PWA, HTTPS gateway, approval inbox or tested notification privacy.
7. No on-server 24/7 scheduler, job workers or automatic recovery. The queue is a deterministic reference implementation.
8. Real domain applications (care, finance, law, dating, arts) remain strict future integration gates; no data processing privileges are implied.
9. The last Codex worktree on the user's VPS has not been independently read in this session; reconcile and merge, never overwrite the latest valid work.
10. No 'superhuman' claim without a preregistered comparative task set, independent raters and a public or reproducible audit.

## Falsification challenge

Reject Apex as an expensive duplication unless its output beats the simpler ChatGPT/Claude/Codex workflow in at least one preregistered task class, at a fixed time/cost/error budget and on new cases. Re-scope or stop extended development if outcome benefits do not justify continuing. Keep the full founder manifesto as a north star regardless of which component is postponed.
