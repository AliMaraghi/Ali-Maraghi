# Security, boundaries and rollback

No production process, Docker socket, live database, secrets, employer data or
personal account was accessed. No dependency installation, network fetch, paid
API, message, publication, push or deployment was performed for this increment.
Local baseline Git initialization was required by MISSION_CONTRACT.md; no remote.

The four stop-state flags are operator-set per invocation. They are not a
persistent global worker/credential control plane. External execution remains
unavailable in every state; real global stop/revocation is future scope.

Untrusted case/source content cannot configure policy or execute tools. The
default kernel has no external adapter. Explicit operator control and OS isolation
remain necessary; these modules do not sandbox malicious Python or the owner.
The existing legacy monitor/service are separate code and do not automatically
inherit the kernel's policy. Do not run them in this restricted development task.

Privacy is deliberately restrictive: only declared public/synthetic evidence
enters the kernel. This is not content-sensitive DLP, encrypted dossier storage,
consent authentication or GDPR certification. Source archives stay private and
are referenced by hashes/line numbers without copied intimate text in reports.
The baseline local commit contains the original private reference files. Never
publish this repository or its Git history without a separate privacy review.

Legacy repairs: read-only health query; bounded connection/statements; denied
feed redirects; bounded bytes/read waits; DTD/entity rejection; strict links;
descriptor-based bounded CLI reads; backup umask before output. Only mocked local
tests ran. The feed elapsed deadline is cooperative, not a strict OS watchdog.
DNS trust, proxy environment, live service behavior and deployment isolation remain
unverified. The backup example still requires encrypted off-site storage and a
real restore drill; it was syntax-checked, not executed.

## Recovery procedures

1. Before reverting code, inspect `git status` and save any new work in a local
   commit or patch. The preserved pre-increment snapshot is `61adae7`. Never use
   destructive reset/clean on an unknown working tree. To revert the increment
   later, review and `git revert` its commit, keeping immutable sources intact.
2. Local experiment rollback is `Ledger.rollback(key, domain, known_version)`.
   A new event changes the selected experiment pointer without deleting failure
   evidence. It does not roll back application files or external operations.
3. Stop local writers before copying `runtime/kernel.sqlite3`. Keep any recovery
   copy inside this workspace and private; use SQLite's backup API for a running
   process, not a raw file copy. Open the copy and run `Ledger.verify()` before
   using it. No production/off-site restore is claimed by this procedure.
4. A detected hash-chain failure blocks append/read. Preserve the damaged file for
   inspection; never silently rebuild a clean chain around corrupted records.

The single local database is mode 0600 under mode 0700 runtime storage. The owner
can rewrite an entire chain or replace code; external anchoring/access isolation
is future work. Deletion/retention/encryption for real personal data is not ready.

Approval is required before enabling any paid adapter, personal account access,
external write action, employer-data access, infrastructure change or deployment.
