# Apex Epoch — Execution programme and acceptance contract

## Governance principle

A founder's visionary document is a **specification of desired behaviour**, not proof of implementation. Preserve all original goals, but promote only verified software, field tests, installed integrations and permitted operational release. The 21-day assessment window is 9–30 November 2026; the end date is an investment/strategy decision, not guaranteed completion of all objectives.

## Stage 0: Forensic reconciliation, zero invention

Read the real `apexdev` repository Git HEAD, status, branches, last good commit, recent Codex files, tests, reports, code files and canonical manifests. Do not assume `05c3cd5` is still the latest commit. Compare ZIP against installed version by SHA. Never reset or force-push the existing repository. Create isolated `import/apex-epoch` branch and retain the original before cherry-picking. Treat the current ZIP as a reference-only code proposal.

Deliverables: baseline SHA, exact test list with skips, source registry, security review, dependency lock, existing gaps, code-to-requirement map, signed `baseline.json` with exact environment metadata. Failed or skipped checks are not passes.

## Stage 1: Constitutional API and value-creating kernel

Reconcile four-plane contracts; build proper migrations and event/audit schema. Implement evidence source/claims/conflicts/provenance graph; documented domains and isolation; typed agent calls; deterministic gateway and zero spend. No network access except from approved source adapters; no uncontrolled model-generated SQL or shell execution. Test actual persistence, concurrency, restart/replay, misconfigured policy, idempotency, capability revocation, four kill stages, audit tampering and lifecycle correctness.

Acceptance: every gateway negative test passes; no high-risk action without an owner token with correct scope and expiry; founder manuscript unchanged; operational reviews of retries and recovery.

## Stage 2: OWP and Negative-Space with real proof

Create legal primary-source connectors in separate sandboxes; add broad dynamic source expansion across markets, countries and industries. Store original snippets or permitted metadata with stable references and hashes. Build gap hypotheses, rejected alternatives, real-world capture constraints, customer demand validation, scenario economics and independent audit. Do not use fake source freshness. Compare opportunity recommendations to ordinary search/ChatGPT at equal time and money budgets. No live contact, bidding or purchases without explicit approval.

Acceptance: three independently source-backed opportunity candidates in three distinct sectors/geographies with dates; one realistic owner-authorised test plan; calibrated false positive ledger; all unverified cases labelled unverified. A sale/profit claim requires actual verified payment/accounting data.

## Stage 3: Durable autonomous operations, not endless loops

Design and test worker execution independent of Codex. Real queue persistence, locks, lease expiry, backoff, dead-letter, alerts, budget reservation, kill-switch drill, backup and offsite restore. Test failure by killing workers, disconnecting APIs, expiring tokens and restarting DB. Security fixes and new features are promoted only through owner-approved staging->production. Use pinned images/digests and migration rollback. Establish a service-level objective measured over sufficient time; do not claim continuous operation from a one-off health check.

Acceptance: test record of recovery and bounded spend; valid private network access; no public DB/n8n API exposure; overnight uptime measurement with logged incidents.

## Stage 4: iPhone owner command centre

Private PWA with actual owner auth, TLS, access auditing, session expiry, locked previews, safe notification payloads, status, tasks, budget, citeable research, experiment ledger, approvals, four kill stages, rollback and version status. Use accessible UI suitable for rapid mobile actions, with approval language clear and audited. Do not expose mobile endpoints to the internet by changing the service bind to `0.0.0.0` without a secure reverse proxy and auth.

Acceptance: from iPhone with laptop OFF, owner successfully views current job + evidence, initiates one approved low-risk task, rejects a high-risk task and sees audit and kill statuses. Recovery from network failure checked.

## Stage 5: Application and differentiation labs

Value systems: economic opportunities, Ali Auteur Studio, professional strategy, lifestyle/social assistance, personal CFO with legal dated sources. Each is a domain module with a separate policy and evaluation harness. The full 18-specialist roster remains as capability-gated roles, not required concurrent agents. Build objective/subjective benchmarks, realistic baselines, independent graders and provenance-backed outcomes.

Creative acceptance: original 60–90-second film made from licensed/owner-authorised assets, real rendered file, original rights-cleared music/voice, QC report, blind review and financial cost ledger. Producing a JSON storyboard does NOT count.

Cross-domain A01–A09 original acceptance files remain binding and distinct from the numbered sections. Each accepted claim needs code location, test command, fixture source, source hash, result and reviewer/date. Status taxonomy: `PASS`, `PARTIAL`, `FAIL`, `BLOCKED`, `NOT TESTED`. A synthetic demonstration can be `PARTIAL` for a subrequirement but never an A01–A09 overall PASS.

## Failure containment and prioritisation

P0: private data leak, policy bypass, unsafe action, budget overspend or unrecoverable loss. Stop and fix; no autonomy expansion.
P1: incorrect evidence/claim promotion, lost jobs or low test reliability. Fix before scoring new opportunities.
P2: UX, narrative, model cost optimisations. Build when P0/P1 are stable.

Every session should leave one or more meaningful commits, a verified test report, an exact failing case if applicable and a next runnable task. No forced time promises, no speculative status dashboards, no claims of overnight autonomous development when Codex has stopped.
